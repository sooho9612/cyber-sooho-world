# Cyber Sooho — UI 공간·미니멀 지침

> **시각 언어**는 [`CONSTITUTION.md`](../CONSTITUTION.md) (Windows Classic 복각)가 우선한다.  
> 이 문서는 그 위에서 **오너 취향**: 공간 효율, 불필요 요소 제거, 미니멀 밀도를 고정한다.  
> Classic ≠ 넓은 여백. **제약은 복각, 밀도는 아끼기.**

---

## 0. 한 줄 원칙

1. **안 써도 되면 안 쓴다** — 장식·중복 라벨·설명 문구·빈 칸을 기본값으로 넣지 않는다.  
2. **공간은 비싸게** — 같은 정보는 더 작은 면적에, 관련 UI는 **붙여** 배치한다.  
3. **본문이 이긴다** — 크롬·말풍선·툴바가 캐릭터·콘텐츠를 가리면 실패다.  
4. **짧은 카피 + 아이콘** — 긴 버튼 문구보다 아이콘+짧은 동사가 우선이다.

헌법 §0.4와 같다: Web 1.0 매력은 “여백의 미”가 아니라 **제약 속 표현**이다.

## 1. 레이아웃 · 여백

### Do

- **관련 블록은 flush** — 무대/리스트와 바로 아래 툴바·액션바 사이에 장식용 갭·틸 띠·`margin`을 두지 않는다. 한 프레임(공통 외곽선)으로 묶는 것을 선호.
- **패딩은 기능 단위만** — 클릭·가독성에 필요한 최소 inset (`6px` 전후). “숨 쉴 공간”용 24px+ 여백을 UI 사이에 끼우지 말 것.
- **카운터·힌트는 안에** — `남은 글자 N`처럼 입력칸 **밖**에 별도 칸을 만들지 말고, 입력 필드 **우측 내부**에 숫자만 올린다.
- **한 줄에 끝내기** — 툴바는 `입력 | 저장 | 삭제`처럼 한 줄·짧은 랩. 불필요한 두 번째 행을 만들지 않는다.

### Don’t

- 섹션 사이 “숨 고르기”용 큰 `gap` / `marginTop`
- 카드·패널을 또 감싸서 이중 테두리 + 이중 패딩
- 플레이스홀더와 별도로 같은 말을 반복하는 헬프 텍스트
- 모던 랜딩식 넓은 whitespace (헌법 Forbidden UI와 동일 방향)

### 예시 (광장 polish)

| Before | After |
|--------|--------|
| 광장 ↔ 말풍선 툴바 사이 틸 여백 | 공통 보더로 **붙임** |
| `남은 글자 40` 별도 텍스트 | 입력칸 **안쪽** 숫자만 |
| `말풍선 저장` / `내 말풍선 삭제` | `💾저장` / `🗑삭제` |

## 2. 카피 · 컨트롤

### Do

- 버튼: **아이콘 + 짧은 동사** (`저장`, `삭제`). 주어·목적어를 라벨에 반복하지 않는다.  
  - 예: `내 말풍선 삭제` → `삭제` (문맥상 대상이 분명하면 충분)
- 플레이스홀더는 **행동 유도 한 줄**만. 기능 설명 괄호를 붙이지 않는다.  
  - 예: `짧은 한마디(말풍선)` → `메세지를 남겨줘!` / `Leave a message!`
- 제한은 **짧게** 잡는다 (예: 말풍선 15자). 긴 텍스트 UI를 전제로 레이아웃하지 않는다.
- ko/en은 헌법 §6대로 **동시에**. 영문도 짧게 유지해 크롬이 안 깨지게.

### Don’t

- 버튼마다 `○○를 △△하기` 식 장문
- 아이콘과 의미가 겹치는 긴 부제
- “남은 글자”, “문자 수” 등 **자명한 접두어**를 숫자 옆에 상시 노출
- 쓰이지 않는 설정·토글·프리뷰 패널을 “나중에 쓸까 봐” 미리 배치

## 2.1 하이라이트 · 호버 대비 (필수)

사이트에 `button:hover { background: #000080; color: white }` 류의 **파란 선택/호버**가 있다.  
파란 fill 위에서는 **글자·아이콘이 흰색**이어야 한다. 검정 고정은 읽히지 않는다.

### Do

- 호버/선택 시 배경이 `#000080`(또는 Highlight)이면 라벨은 **`#fff` / `white` / `currentColor` / `inherit`**.
- 버튼 안 **자식 `<span>`·아이콘**도 부모 `color`를 따르게 한다. 자식에 `color: #000`을 하드코딩하지 않는다.
- 선택(selected)과 호버(hover) **둘 다** 같은 대비 규칙을 적용한다.

### Don’t

- 파란 fill + 자식만 `color: '#000'` / `color="black"` (제어판 아이콘 라벨 사고 유형)
- 호버는 파란데 라벨만 검정으로 남는 구조
- “선택일 때만 흰색, 호버는 무시” — 호버도 동일하게 대비 확보

### 체크

- [ ] 호버했을 때 라벨이 파란 위에서 **흰색**으로 보이는가?
- [ ] 선택 하이라이트와 호버가 같은 규칙을 따르는가?
- [ ] 버튼 자식(span/SVG)이 부모 color를 가로채지 않는가?

## 3. 가림 · 겹침 · z

### Do

- 오버레이(말풍선, 툴팁, 배지)는 **대상 스프라이트/본문을 덮지 않게** 배치한다.  
  - 구석·가장자리: 위가 막히면 **옆**(꼬리 left/right)으로 보낸다.
- 높이 추정은 **실제 줄바꿈**을 반영한다. 짧게 잡아 겹침 검사를 통과시킨 뒤 화면에선 덮는 실수를 금한다.
- 충돌 시: 장식 유지 < **콘텐츠 가독성**. 캐릭터·닉네임·본문이 우선.

### Don’t

- “말풍선은 항상 머리 위” 같은 고정 앵커만으로 코너를 방치
- z-index만 올려서 가림을 “위에  Gre게” 해결 (위치 해결이 먼저)

## 4. 정보 밀도 체크 (새 UI / polish 시)

작업 전에 스스로 묻는다.

- [ ] 이 여백/갭을 지우면 덜 읽히나? → 아니면 **지운다**
- [ ] 이 라벨이 아이콘·문맥으로 대체 되나? → **짧게 하거나 제거**
- [ ] 보조 숫자/상태가 본 컨트롤 **안**에 들어갈 수 있나? → **안으로**
- [ ] 관련 패널이 시각적으로 한 덩어리인가? → **flush / 공통 프레임**
- [ ] 오버레이가 주인공(캐릭터·본문)을 가리나? → **자리 이동**
- [ ] “있으면 fancy한데 없어도 되는” 컨트롤인가? → **넣지 않는다**
- [ ] 헌법 Classic 베벨·팔레트는 유지한가? → 미니멀해도 **복각은 깨지 않음**
- [ ] 파란 호버/선택 위 라벨·아이콘이 **흰색**인가? (§2.1)
