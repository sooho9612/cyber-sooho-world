## 제품 모델

- **잔류형 놀이터만** (실시간 동시접속·같이 걷기·하이브리드 없음)
- 로그인 유저가 캐릭터·말풍선을 남기면 DB에 저장 → 다른 사람(비로그인 포함)이 나중에 와도 보임

### 화면 갱신 (용어)

| 방식 | 의미 |
|------|------|
| fetch / 재진입 | 열 때·탭 복귀 시 DB 한 번 읽기 |
| Realtime 구독 | 테이블 변경 시 자동 다시 그리기 (걷기는 아님) |

→ MVP는 fetch로 충분. Realtime은 코딩 계획에서 선택 보강.

---

## 캐릭터·배치

- 스프라이트 **1종** + **닉네임** 구분 (다중 선택·커스텀은 나중)
- **서기(stand)** 스팟만 (앉기 나중)
- PC **클릭** / 모바일 **터치** → **즉시 텔레포트**
- 서로 너무 안 겹치게 **최소 간격**
- **유저당 캐릭터 1개**

---

## 말풍선

- 공간 위 **짧은 한 줄**만 (채팅 로그 UI 없음)
- **영구**, **1인 1말풍선**, 수정 = overwrite, 본인 삭제 + 관리자 강제 삭제
- 글자 수 제한 + 말풍선끼리 **겹침 최소화**
- 다국어 글리프 가능한 픽셀/도트 계열 폰트 (+ fallback)

---

## 권한

- 로그인: 본인 배치·이동·말풍선 CRUD(본인)
- 비로그인: 구경만
- owner: 타인 캐릭터·말풍선 삭제

## MVP In / Out

**In:** Intro→광장, 배경 1장, 스탠드+텔레포트, 1종 캐릭터, 1인1 말풍선, 관람/관리자/ko·en, 방명록·공지 유지  

**Out:** 실시간 걷기, 앉기, 다중 캐릭터, 로그, 멀티맵, TTL
